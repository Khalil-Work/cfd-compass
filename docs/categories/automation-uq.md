## ⚙️ Automation, optimization & uncertainty

Workflow orchestration, adjoints, sensitivity analysis and uncertainty quantification.

| Project / use case | What it offers | Selection notes |
| --- | --- | --- |
| **[AeroSandbox](https://github.com/peterdsharpe/AeroSandbox)**<br>Aircraft design and aerodynamic screening | Python aircraft design and optimization environment using automatic differentiation and composable engineering analyses. Useful for rapid aerodynamic design exploration and multidisciplinary studies before committing to higher-fidelity CFD evaluations.<br>[Docs](https://aerosandbox.readthedocs.io/) · `MIT` | Established · Many included methods are reduced-fidelity engineering models; do not equate all analyses with Navier–Stokes CFD. |
| **[Chaospy](https://github.com/jonathf/chaospy)**<br>Polynomial-chaos CFD uncertainty studies | Numerical toolbox for polynomial chaos, sampling and quadrature. Useful for propagating uncertain flow parameters through CFD surrogates or moderately priced solvers and building nonintrusive uncertainty-expansion experiments.<br>[Docs](https://chaospy.readthedocs.io/) · `MIT` | Established · High-dimensional or discontinuous response surfaces may require alternatives to a simple polynomial expansion. |
| **[Dakota](https://github.com/snl-dakota/dakota)**<br>External-solver design exploration and UQ | Design exploration framework combining optimization, parameter estimation, sensitivity analysis and uncertainty quantification. Useful for managing repeated CFD evaluations and propagating uncertain inputs through external engineering simulation models.<br>[Docs](https://snl-dakota.github.io/docs/latest_release/) · `NOASSERTION` | Established · Requires a working simulation interface and can demand many expensive flow evaluations. |
| **[foamlib](https://github.com/gerlero/foamlib)**<br>Automated OpenFOAM case management | Python interface for OpenFOAM files, cases and execution. Useful for reproducible parameter studies, programmatic field access and reducing repetitive case-management steps around an existing OpenFOAM installation.<br>[Docs](https://foamlib.readthedocs.io/) · `GPL-3.0` | Emerging · OpenFOAM must be installed separately; confirm support for the selected distribution and file types. |
| **[MPhys](https://github.com/OpenMDAO/mphys)**<br>Modular high-fidelity MDO | Standardizes high-fidelity multiphysics problems within OpenMDAO using modular conventions and solver integrations. Useful for assembling CFD–structures or aerothermal studies while preserving coupling and derivative interfaces across disciplines.<br>[Docs](https://openmdao.github.io/mphys/) · `NOASSERTION` | Established · It is an integration layer; individual examples require compatible external solvers and their dependencies. |
| **[OpenMDAO](https://github.com/OpenMDAO/OpenMDAO)**<br>Coupled engineering optimization | Python framework for tightly coupled systems analysis and multidisciplinary optimization. Useful for connecting CFD, structures and engineering models while managing derivatives, nonlinear coupling and parallel model execution.<br>[Docs](https://openmdao.org/newdocs/versions/latest/) · `NOASSERTION` | Established · CFD analysis components and reliable derivatives must be supplied; it does not replace a flow solver. |
| **[OpenTURNS](https://github.com/openturns/openturns)**<br>Probabilistic CFD study design | C++ and Python library for probabilistic modelling and uncertainty treatment in industrial studies. Useful for wrapping CFD evaluations, defining uncertain inputs and constructing reliability, sensitivity or surrogate analyses.<br>[Docs](https://openturns.github.io/openturns/latest/) · `NOASSERTION` | Established · Physics and solver interfaces remain application-specific; verify sampling accuracy and assumptions about input distributions. |
| **[pyOptSparse](https://github.com/mdolab/pyoptsparse)**<br>Sparse constrained aerodynamic optimization | Framework for defining and solving constrained nonlinear optimization problems with sparse derivatives. Useful as an optimization driver around aerodynamic CFD models and other expensive engineering analyses with many constraints.<br>[Docs](https://mdolab-pyoptsparse.readthedocs-hosted.com/en/latest/) · `LGPL-3.0` | Established · Some optimizer backends require separate proprietary licenses; check the chosen backend and installation. |
| **[RAVEN](https://github.com/idaholab/raven)**<br>Simulation orchestration and risk/UQ studies | Simulation workflow framework for uncertainty quantification, optimization, model reduction and probabilistic risk analysis. Useful for orchestrating external CFD studies, sampling parameter spaces and training surrogates around expensive evaluations.<br>[Docs](https://github.com/idaholab/raven#readme) · `Apache-2.0` | Established · Requires model interfaces, configuration and domain-specific validation; probabilistic output is only as reliable as its assumptions. |
| **[SALib](https://github.com/SALib/SALib)**<br>Global sensitivity of CFD outputs | Python implementations of global sensitivity-analysis methods such as Sobol and Morris. Useful for ranking uncertain CFD inputs after sampling and evaluating a separate solver or surrogate model.<br>[Docs](https://salib.readthedocs.org/) · `MIT` | Established · Generates designs and analyzes outputs; the user supplies solver runs and checks estimator convergence. |
| **[UQpy](https://github.com/SURGroup/UQpy)**<br>Programmable CFD uncertainty workflows | General Python toolbox for modelling uncertainty in physical and mathematical systems. Useful for uncertainty propagation and surrogate-based analyses around CFD models when sampling and probabilistic workflows need programmable control.<br>[Docs](https://uqpyproject.readthedocs.io/) · `MIT` | Established · A general UQ library rather than a CFD package; connect and validate the simulation model separately. |
