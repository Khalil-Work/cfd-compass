## 🧮 Numerical infrastructure & parallel computing

PDE assembly, adaptive grids, linear algebra and performance backbones used to build CFD applications.

| Project / use case | What it offers | Selection notes |
| --- | --- | --- |
| **[AMReX](https://github.com/AMReX-Codes/amrex)**<br>Building adaptive parallel CFD applications | Block-structured adaptive-mesh framework supplying parallel data structures, particles, embedded boundaries and CPU/GPU infrastructure for building CFD applications; it does not provide a single configured flow model.<br>[Docs](https://amrex-codes.github.io/amrex/docs_html/) · `NOASSERTION` | Established · Application developers must supply governing equations, discretizations and physical models. Match the framework revision and accelerator configuration to the consuming solver. |
| **[deal.II](https://github.com/dealii/dealii)**<br>Adaptive finite-element solver development | C++ adaptive finite-element library providing meshes, finite-element spaces, assembly and parallel algorithms for custom CFD programs, including documented flow examples rather than one universal ready-to-run solver.<br>[Docs](https://www.dealii.org/) · `NOASSERTION` | Established · A numerical development library; the application determines governing equations and stable discretization. Optional PETSc, Trilinos and p4est dependencies must be version-compatible. |
| **[DOLFINx / FEniCSx](https://github.com/FEniCS/dolfinx)**<br>Programmable finite-element flow formulations | C++ and Python finite-element environment for expressing and assembling PDE problems, useful for programmable Navier-Stokes studies; users still formulate weak forms, constraints, boundary conditions and solver strategies.<br>[Docs](https://docs.fenicsproject.org/dolfinx/main/python/) · `LGPL-3.0` | Established · DOLFINx is the FEniCSx computational component, not a standalone packaged CFD model. Follow documentation matching the installed release and compatible FEniCSx dependencies. |
| **[Ginkgo](https://github.com/ginkgo-project/ginkgo)**<br>Portable GPU sparse-system backends | C++ sparse linear-algebra library targeting many-core CPUs and GPUs, useful inside CFD pressure or coupled-system solvers; users provide matrices and algorithms appropriate to their discretized equations.<br>[Docs](https://ginkgo-project.github.io/ginkgo-generated-documentation/doc/develop/) · `BSD-3-Clause` | Established · A linear-algebra backend, not a CFD application. Benchmark complete solver convergence and data movement; accelerator support does not guarantee faster end-to-end simulation. |
| **[hypre](https://github.com/hypre-space/hypre)**<br>Parallel multigrid pressure-system solution | Parallel sparse-system library featuring algebraic and structured multigrid methods, useful for CFD pressure and diffusion solves; it supplies numerical components rather than a turnkey fluid simulation.<br>[Docs](https://hypre.readthedocs.io/en/latest/) · `NOASSERTION` | Established · Select an interface and preconditioner appropriate to matrix structure and symmetry; GPU support varies by algorithm and build. Current licensing is Apache-2.0 OR MIT. |
| **[Kokkos Core](https://github.com/kokkos/kokkos)**<br>Portable CFD kernel implementation | C++ performance-portability programming library abstracting parallel execution and memory layouts, useful for implementing CFD kernels across CPU and GPU architectures; it supplies no governing equations or flow solver.<br>[Docs](https://kokkos.org/kokkos-core-wiki/) · `NOASSERTION` | Established · Performance portability still requires algorithm, layout and backend choices. Check compiler and device support for the chosen release; numerical correctness remains the application's responsibility. |
| **[libCEED](https://github.com/CEED/libCEED)**<br>Portable high-order operator kernels | Library for factored finite-element operator evaluation across CPU and GPU backends, enabling matrix-free high-order CFD implementations; its algebraic interface integrates into applications rather than defining their complete physics.<br>[Docs](https://libceed.org/en/latest/) · `BSD-2-Clause` | Established · Applications retain mesh, parallel decomposition and solver responsibilities. Backend behavior and deterministic capabilities vary; bundled fluid miniapps illustrate integration rather than certify arbitrary CFD models. |
| **[MFEM](https://github.com/mfem/mfem)**<br>High-order finite-element flow research | Modular parallel finite-element library with high-order spaces, adaptive meshes and operator infrastructure for developing CFD discretizations; examples and miniapps are building blocks rather than complete engineering workflows.<br>[Docs](https://mfem.org/) · `BSD-3-Clause` | Established · Users select stable spaces, weak forms, boundary conditions and solvers. Reproducing an example does not establish the suitability of a newly assembled flow formulation. |
| **[p4est](https://github.com/cburstedde/p4est)**<br>Distributed tree-based adaptive CFD meshes | Parallel forest-of-octrees library managing adaptive mesh refinement, coarsening and partitioning, useful beneath scalable CFD discretizations; the consuming application supplies numerical fluxes, physical fields and time evolution.<br>[Docs](https://www.p4est.org/) · `GPL-2.0` | Established · Mesh infrastructure rather than a flow solver. Official guidance warns that auto-generated GitHub source archives lack required components; use maintained release tarballs or initialize dependencies correctly. |
| **[PETSc](https://github.com/petsc/petsc)**<br>Scalable coupled CFD solver infrastructure | Parallel numerical toolkit providing sparse algebra, nonlinear solvers, time integration and distributed meshes for CFD implementations; application code still supplies the flow equations, discretization and boundary conditions.<br>[Docs](https://petsc.org/release/) · `NOASSERTION` | Established · Official GitHub mirror; primary development and issue tracking are on GitLab. Solver/preconditioner choices and nullspace handling must match the discretized problem. |
| **[SUNDIALS](https://github.com/llnl/sundials)**<br>Stiff reacting-flow integration components | Time-integration and nonlinear-solver libraries for differential and algebraic systems, useful for stiff chemistry and semidiscrete CFD equations; applications supply spatial operators, physical models and appropriate solver interfaces.<br>[Docs](https://sundials.readthedocs.io/en/latest/) · `BSD-3-Clause` | Established · Not a spatial CFD solver. Choose tolerances, Jacobians, vector backends and preconditioners for the actual stiffness and conservation requirements; keep package versions consistent. |
